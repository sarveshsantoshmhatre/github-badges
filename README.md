# GitHub Achievements Guide

A practical, honest guide to earning GitHub profile achievements through useful repository work.

GitHub awards achievements automatically when qualifying events occur. This repository documents common achievements, their publicly observed criteria, and ways to work toward them without manufacturing activity.

## Common achievements

| Achievement | How it is commonly earned | Notes |
| --- | --- | --- |
| Pull Shark | Have pull requests merged | Community-maintained references report tiers at 2, 16, 128, and 1,024 merged pull requests. |
| Pair Extraordinaire | Have a co-authored commit included in a merged pull request | Requires genuine collaboration and accurate co-author attribution. |
| Quickdraw | Close an issue or pull request within five minutes of opening it | Use this only for a legitimate issue or pull request that is ready to close. |
| YOLO | Merge a pull request without a review | Available only when repository settings and protections permit it. |
| Galaxy Brain | Have answers accepted in GitHub Discussions | Depends on helpful answers and acceptance by discussion participants. |
| Starstruck | Create a repository that attracts stars | Requires genuine interest from other developers. |
| Public Sponsor | Sponsor an eligible developer through GitHub Sponsors | This involves a real financial contribution. |

Achievement rules and availability can change. GitHub's profile reference is the primary source for official achievement information; treat thresholds not explicitly shown there as community-reported, not guaranteed.

## A productive workflow for this repository

1. Pick an actual improvement, such as fixing this guide, adding verified sources, or improving accessibility.
2. Create a focused branch for the change.
3. Open a pull request with a clear problem statement and summary.
4. Review the diff, test any code or links, and merge only when the change is useful.
5. Record sources and uncertainty so contributors can keep the guide accurate.

## How to contribute

Open a pull request with a specific correction or improvement. Prefer official GitHub documentation for eligibility rules, and label community observations clearly. Review [CONTRIBUTING.md](CONTRIBUTING.md) before submitting a change.
